# Журнал студии — отдельный сайт

Полная копия функциональности «Журнала студии» (Лента, Доска ретро, Новая запись, категории,
черновики) в виде самостоятельного веб-приложения: своя база данных, свой вход по email
(без пароля, только адреса `@ze.studio`), свой домен. Не привязано к аккаунтам claude.ai.

Стек: **Next.js 14** (React) + **Supabase** (Postgres, Auth, Realtime) + **Vercel** (хостинг).

Всё, что ниже — разовая настройка. После неё сайт работает сам: команда заходит по ссылке
на почту, записи сохраняются в общую базу и появляются у всех в реальном времени.

---

## Что нужно сделать (по шагам)

### 1. Создать проект Supabase

1. Зайдите на [supabase.com](https://supabase.com), зарегистрируйтесь / войдите.
2. New Project → укажите название (например, `studio-journal`), пароль базы данных (сохраните
   его отдельно, дальше не понадобится) и регион (ближайший к команде).
3. Дождитесь, пока проект создастся (1–2 минуты).

### 2. Выполнить схему базы данных

1. В панели проекта откройте **SQL Editor** → **New query**.
2. Откройте файл `supabase/schema.sql` из этого проекта, скопируйте содержимое целиком.
3. Вставьте в редактор и нажмите **Run**.
4. Должно отработать без ошибок — это создаст таблицы `profiles` и `entries`, правила доступа,
   ограничение регистрации доменом `@ze.studio` и несколько примеров записей для затравки.

   Если у студии другой почтовый домен — до запуска замените `ze.studio` на нужный домен
   в двух местах файла (строка с `'@ze.studio'` в функции `enforce_org_domain` и текст
   сообщения об ошибке рядом).

### 3. Настроить Auth (вход по ссылке)

1. В панели Supabase: **Authentication → URL Configuration**.
2. **Site URL** — укажите будущий адрес сайта (например, `https://journal.ze.studio`). Пока
   домена нет, можно временно указать адрес, который выдаст Vercel на шаге 5, и вернуться
   сюда позже.
3. **Redirect URLs** — добавьте `<ваш-адрес>/auth/callback` (и то же самое с `http://localhost:3000/auth/callback` для локальной разработки, если понадобится).
4. Email-провайдер для отправки писем со ссылкой включён по умолчанию (Supabase Auth), ничего
   дополнительно настраивать не нужно для первого запуска. Письма будут приходить от адреса
   Supabase — при желании позже можно подключить свой домен для писем в **Authentication → Emails → SMTP Settings**.

### 4. Получить ключи проекта

1. В панели Supabase: **Settings → API**.
2. Скопируйте **Project URL** и **anon public** ключ — они понадобятся на следующем шаге.

### 5. Задеплоить на Vercel

Самый простой способ — через GitHub:

1. Залейте содержимое этой папки в новый репозиторий на GitHub (можно приватный).
2. Зайдите на [vercel.com](https://vercel.com), New Project → Import из вашего GitHub-репозитория.
3. В настройках проекта, до первого деплоя, добавьте переменные окружения
   (**Environment Variables**):
   - `NEXT_PUBLIC_SUPABASE_URL` — Project URL из шага 4
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY` — anon-ключ из шага 4
4. Нажмите **Deploy**. Через минуту сайт будет доступен по адресу вида
   `studio-journal-xxxx.vercel.app`.
5. Вернитесь в Supabase (шаг 3) и обновите **Site URL** / **Redirect URLs** на этот
   реальный адрес, если указывали временный.

Альтернатива без GitHub — через Vercel CLI из этой папки:
```bash
npm install -g vercel
vercel login
vercel --prod
```
(переменные окружения тогда нужно будет добавить командой `vercel env add`, или в интерфейсе
Vercel после первого деплоя).

### 6. Подключить домен студии (например, journal.ze.studio)

1. В панели Vercel: **Project → Settings → Domains** → добавьте `journal.ze.studio`.
2. Vercel покажет DNS-запись, которую нужно добавить у регистратора домена `ze.studio`
   (обычно CNAME-запись на `cname.vercel-dns.com`). Добавьте её там, где вы управляете DNS
   студии.
3. Когда DNS обновится (от нескольких минут до пары часов), Vercel подтвердит домен и выдаст
   SSL-сертификат автоматически.
4. Не забудьте обновить **Site URL** в Supabase (шаг 3) на финальный адрес `https://journal.ze.studio`.

## Дальше сайт не требует обслуживания

- Все в команде заходят на сайт и вводят рабочую почту `@ze.studio` — приходит письмо со
  ссылкой, по ней происходит вход. Пароль не нужен и нигде не хранится.
- Кто-то с другим доменом почты войти не сможет — это ограничение включено на уровне базы
  данных (шаг 2), а не только в интерфейсе.
- Все записи хранятся в Supabase и видны всей команде в реальном времени — если один человек
  добавляет запись, она сразу появляется у остальных без обновления страницы.
- Примеры записей (помечены как «пример») можно удалить прямо в интерфейсе после того, как
  появятся первые настоящие записи.

## Локальная разработка (по желанию)

```bash
npm install
cp .env.example .env.local   # и вписать туда ключи из шага 4
npm run dev
```
Сайт откроется на `http://localhost:3000`.

## Структура проекта

```
app/                 страницы (Next.js App Router)
  layout.js           общий каркас, шрифты
  page.js              главная страница (весь интерфейс)
  login/page.js        страница входа по email
  auth/callback/       обработка ссылки из письма
  globals.css          вся визуальная стилистика
components/
  JournalApp.js         основной компонент: лента, доска ретро, форма новой записи
  ItemRow.js             карточка одной записи
lib/
  journal-constants.js   категории, типы, статусы, цвета
  supabase/               обёртки клиента Supabase (браузер / сервер)
middleware.js             защита страниц: без входа — редирект на /login
supabase/schema.sql        схема базы данных — выполнить один раз в Supabase
```

## Как это соотносится с версией в Claude

Ранее собранная версия «Журнал студии» как Claude Artifact продолжает существовать и доступна
всем, у кого есть доступ к организации в claude.ai — она никуда не делась. Этот сайт — не
дополнение к ней, а самостоятельная замена для случаев, когда у части команды нет аккаунтов
claude.ai: тот же дизайн, та же логика, но со своим входом и своей базой данных, независимо
от Claude. Поддерживать обе версии параллельно не нужно — после запуска сайта имеет смысл
пользоваться им как основным инструментом команды.
