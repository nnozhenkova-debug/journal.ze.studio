# Журнал студии

Внутренний инструмент ze.studio: календарь ретро-сессий, шесть шаблонов
фасилитации, проекты с этапами и бюджетом часов, проблемы и общая лента
событий команды.

## Что внутри

- **Главный экран** — календарь месяца с отметками ретро, быстрый запуск
  любого из шести шаблонов, свежие открытые проблемы и лента последних
  событий.
- **Подготовка к ретро** (`/retro/prepare`) — перед стартом ПМ выбирает
  метод и этап проекта и сразу видит описание метода, шаги фасилитации и
  контекст: сколько часов потрачено на этап и какая это доля от бюджета
  всего проекта.
- **Живая ретро-сессия** (`/retro/[id]`) — колонки под выбранный шаблон,
  карточки добавляются в реальном времени всем участникам (Supabase
  Realtime). Три состояния: сессия идёт → итоги (черновик) → опубликовано
  в ленте.
- **Проекты** (`/projects`) — каталог и карточка проекта: этапы, бюджет
  часов, проблемы, история ретро.
- **Проблемы** (`/issues`) — общий список по всем проектам, с фильтрами
  открытые/решённые и отметкой «решено» прямо из списка.
- **Лента** (`/events`) — все события студии: завершённые ретро, решённые
  проблемы и новые проблемы.
- **Команда** (`/team`) и **Профиль** (`/profile`) — состав студии и
  личные настройки (имя, роль, уведомления).

Шесть шаблонов ретро — Старт·Стоп·Продолжай, 4L, Mad·Sad·Glad, Парусник,
DAKI, Энергия команды — описаны в `lib/retro-constants.js` вместе с
шагами фасилитации для каждого.

## Технологии

- Next.js 14 (App Router), React 18
- Supabase (Postgres + Auth + Realtime) через `@supabase/ssr`
- Обычный CSS с токенами дизайн-системы (без Tailwind) — `app/globals.css`
- Шрифт Geist (`geist/font/sans`)

## Развёртывание

### 1. Создайте проект Supabase

На [supabase.com](https://supabase.com) создайте новый проект (бесплатного
тарифа достаточно).

### 2. Примените схему базы данных

Откройте **SQL Editor → New query** в Supabase Dashboard, вставьте
содержимое `supabase/schema.sql` целиком и нажмите **Run**. Файл
безопасно выполнять повторно — все команды идемпотентны (`if not exists`,
`on conflict do nothing`).

Схема создаёт таблицы `profiles`, `projects`, `project_stages`, `retros`,
`retro_participants`, `retro_notes`, `issues`, `events`, включает Row
Level Security и Realtime для `retros`/`retro_notes`/`issues`/`events`, а
также добавляет тестовые данные (проекты «Аврора», «Нова», «ze.studio» с
этапами, проблемами и событиями) — их можно удалить из интерфейса, когда
появятся настоящие проекты.

По умолчанию регистрация ограничена доменом `@ze.studio` — поменяйте его
в функции `enforce_org_domain` в начале `schema.sql`, если домен почты
команды другой.

### 3. Создайте аккаунты сотрудников

В Supabase Dashboard **Authentication → Users → Add user** создайте
аккаунт для каждого сотрудника (почта на корпоративном домене + пароль),
включите **Auto Confirm User**. Профиль в `profiles` создастся
автоматически.

### 4. Получите ключи API

**Project Settings → API**: скопируйте `Project URL` и `anon public` key.

### 5. Разверните на Vercel

Через GitHub:

1. Запушьте этот код в репозиторий на GitHub.
2. На [vercel.com](https://vercel.com) — **Add New → Project**, выберите
   репозиторий.
3. В **Environment Variables** добавьте:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
4. Deploy.

Либо через Vercel CLI: `npm i -g vercel`, затем `vercel` из папки проекта
(добавьте те же переменные окружения при первом деплое или через
`vercel env add`).

### 6. Подключите домен (опционально)

**Project Settings → Domains** в Vercel — например `journal.ze.studio`.

## Локальная разработка

```bash
npm install
cp .env.example .env.local   # впишите NEXT_PUBLIC_SUPABASE_URL и NEXT_PUBLIC_SUPABASE_ANON_KEY
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000).
